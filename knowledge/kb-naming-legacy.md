# 订单域的命名例外：下划线是历史包袱，不要统一

## 结论

订单域对外的字段名**全部是下划线命名**（`order_id`、`create_time`、`pay_status`），与全公司《命名规范》要求的驼峰**不一致**。这是历史遗留，**保持现状，不要统一**。

## 边界

- **是**（保持下划线，不许改）：`trade_order` 及其关联表、订单服务所有对外接口的出参字段
- **不是**（按规范用驼峰）：
  - 2023 年后新建的表（`order_tag`、`order_remark` 等，建表时已按驼峰）
  - 订单服务**内部**的变量名、类名——内部怎么写不影响外部，按规范来

## 最容易搞错的

Agent 读到项目里的《命名规范》文档说"统一驼峰"，在改订单功能时"顺手"把出参的 `order_id` 改成了 `orderId`。这是一次典型的**善意破坏**：代码更规范了，但订单接口有 20 多个下游消费方按 `order_id` 解析，全部解析失败。

**关键点：规范文档是对的，但它没写例外。** 存量系统里几乎每条规范都有例外，而例外恰恰不写在规范里——这正是本知识库存在的意义。

实操建议：把「订单域对外字段名」列进 `plan.md` §6 不改清单，让 Agent 编码时碰不到。
