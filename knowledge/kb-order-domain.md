# 订单域：订单 / 删除 / 退货退款 的边界

## 结论

- **「订单」= 交易订单（`trade_order`）**，不含配送单、售后单。
- **「删除订单」= 用户侧不可见，不是物理删除**。数据保留，走关系表标记隐藏。
- **「退货」和「退款」是两件事**：退货是物流动作，退款是资金动作；可以只退款不退货。

## 边界

- **是**：`trade_order` 主表及其状态流转
- **不是**：`delivery_order`（配送单，物流域）、`aftersale_order`（售后单，售后域）。这三张表的"订单号"格式相同但含义不同，**不能互相当参数传**。
- **是**：删除后该订单在"我的订单"列表不可见
- **不是**：删除后数据从库里消失。财务、风控、客服工单三个下游仍要能查到；物理删除会直接打穿对账。

## 最容易搞错的

PRD 里只写了一句「用户可以删除订单」，Agent 首次理解为物理删除，生成了 `DELETE FROM trade_order`。这会导致：财务对账缺单、客服查不到历史工单、风控模型丢样本。**正确做法是插入隐藏关系记录，列表查询时过滤。**

第二个坑：用户说"我要退货"时，实际诉求往往是退款。直接调退货工具会让用户等物流上门，而他只想要钱回来。**遇到「退货」先确认是否需要寄回商品。**
